# alldot 公网固定入口：复用 relay 域名 + /dot 子路径（2026-11-26 实测可用）

# 结论：不用新 DNS、不用阿里云 Secret。直接复用已解析的 relay.sxliuyu.bond，
#       在它的 Caddy 上加一个 /dot 子路径反代到本机桥。
#
# 链路：手机 --HTTPS--> relay.sxliuyu.bond (123.57.107.21 的 Caddy)
#                    --SSH 反向隧道 18799--> 本机 127.0.0.1:8799 的 alldot 桥
#
# 手机固定入口：https://relay.sxliuyu.bond/dot/chat?token=<桥 token>
# APK 里「电脑 alldot」地址填：https://relay.sxliuyu.bond/dot

## 为什么是 /dot 子路径而不是新子域名
# dot.sxliuyu.bond 需要新加 DNS A 记录，而阿里云 Secret 不在现有凭据里（历史只存了 AccessKey
# LTAI5t7EcGJpgSc1eXh1aauQ）。relay.sxliuyu.bond 已有解析、已有 Let's Encrypt 证书（LE 能到 123，
# 所以证书也能自动续），复用它零 DNS 改动。

## 已做的改动

### 1. 桥支持子路径（chat.html / sw.js / manifest 已改，仓库里）
# - chat.html：BASE = location.pathname.startsWith('/dot/') ? '/dot' : ''；所有 fetch 用 BASE 前缀。
#   页面挂在 /dot/chat 或 /chat 都能用，行为不变。
# - manifest.webmanifest：start_url/scope/图标改相对路径（./chat、icon-192.png）。
# - sw.js：按 self.location 算 BASE，缓存路径带前缀。
# 桥是每次请求 readFileSync 读 chat.html，所以改完不用重启桥就生效。

### 2. 123 的 Caddyfile（/etc/caddy/Caddyfile，已备份 Caddyfile.bak-20261126-213904）
# relay.sxliuyu.bond 站点里加了：
#   handle_path /dot/* {
#       reverse_proxy 127.0.0.1:18799 { flush_interval -1 }
#   }
# handle_path 剥掉 /dot 前缀，桥收到的仍是 /chat、/mcp 等原始路径。
# 已 caddy validate 通过、systemctl reload caddy。

### 3. SSH 反向隧道（本机 -> 123）
#   ssh -N -f -o BatchMode=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 \
#       -o ServerAliveCountMax=3 -i ~/.ssh/sxliuyu_123 \
#       -R 127.0.0.1:18799:127.0.0.1:8799 root@123.57.107.21

### 4. 隧道守护（开机自启 + 断线自愈，已挂进 dot-keeper）
# - 脚本：build/tools/tunnel-keepalive.ps1（幂等：在 123 上 curl 18799/health，通就退出；
#   不通就清残留 ssh 隧道、重连一条）。日志 ~/.allbot/dot/state/tunnel-keepalive.log。
# - dot-keeper 计划任务每 5 分钟以 -Execute 跑 keeper.ps1，keeper 每轮顺带调一次
#   tunnel-keepalive.ps1（dry-run 不跑）。电脑重启后最多 5 分钟隧道自动恢复。
# - 没用独立计划任务：非管理员会话注册 Register-ScheduledTask 被拒（拒绝访问），
#   所以挂在已有的 dot-keeper 上，不需要管理员。

## 已知限制
# - 桥进程若是旧代码（本次 PWA 路由新增前启动的），/dot/manifest.webmanifest、/dot/icon-*.png
#   会 404；重启桥后才有。不影响 APK 用 WebView 加载 /dot/chat（不依赖这两个）。
# - 手机和电脑都要在线：电脑关机/断网，公网入口就不通（这是本地 agent 的固有限制）。
# - relay 域名同时跑着 nanoMuse relay（/healthz、/v1/link），/dot 前缀不冲突。

## 安全
# - 桥 token 仍是唯一鉴权，Caddy 不存 token、只转发。
# - relay 域名已有 HTTPS（Let's Encrypt），手机到 123 这段是加密的。
# - 若要再加一层，可在 /dot 的 Caddy 段加 basicauth，但 APK 侧要能带 Basic 头。
