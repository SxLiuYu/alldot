## 一、手机接入（三种方式）

配置写在 `~/.allbot/dot/config.json` 的 `mobile_access` 段。默认 `loopback`，行为跟以前一样（手机连不上，服务只听 127.0.0.1）。

### 1. 局域网直连（最常用）

同一 WiFi 下手机直接连电脑。

```json
"mobile_access": { "mode": "lan", "allowed_cidrs": [] }
```

- 桥监听 `0.0.0.0:8799`。
- 查电脑内网 IP：`ipconfig` 看「IPv4 地址」，通常是 `192.168.x.x` 或 `10.x.x.x`。
- 手机浏览器打开：`http://<电脑内网IP>:8799/chat?token=<桥token>`
- 桥 token 在 `C:/Users/1/.allbot/dot/bridge-token`。
- 第一次带 `?token=` 访问会种 Cookie（一天有效），后面直接开 `http://<电脑IP>:8799/chat` 就行。

**放行规则**：私网地址（192.168/16、10/8、172.16-31、169.254/16）和本机回环默认放行，公网地址拒绝。要放行额外来源用 `allowed_cidrs`，例如中继服务器 IP：

```json
"mobile_access": {
  "mode": "lan",
  "allowed_cidrs": ["123.57.107.21/32"]
}
```

### 2. 内网穿透（公网可访问）

```json
"mobile_access": { "mode": "tunnel", "allowed_cidrs": [] }
```

- 桥同样监听 `0.0.0.0:8799`，桥本身不知道公网域名。
- 前面自己挂 cloudflared / frp，把流量转到电脑的 8799。
- **前置代理必须做 HTTPS 和鉴权**，桥只认 token，不终止 TLS。
- 隧道把请求转到本机时来源是回环地址，桥默认放行，不冲突。

### 3. 自定义中继

```json
"mobile_access": { "mode": "relay", "allowed_cidrs": ["<你的中继IP>/32"] }
```

- 桥监听 `0.0.0.0:8799`，你的中继负责把手机请求转发进来。
- 中继来源 IP 要写进 `allowed_cidrs`，否则被 403。

### 安全说明

三种模式**都要桥 token**，鉴权没放松。局域网模式在不可信 WiFi（咖啡厅）有风险，建议用 tunnel + HTTPS。`/health` 会报当前接入模式和放行说明，巡检时能一眼看到。

## 二、语音（ASR + TTS）

复用 nanoMuse 已实测的免费语音接口（百度主引擎，Edge/Whisper 兜底），接口形状是 OpenAI 兼容的 `/v1/audio/*`。默认关，开之前要配 key。

### 配置

```json
"voice": {
  "enabled": true,
  "base_url": "https://www.sxliuyu.bond",
  "api_key_env": "ALLDOT_VOICE_API_KEY",
  "voice": "alloy",
  "max_asr_seconds": 58,
  "max_tts_chars": 450
}
```

密钥**不写进配置**，放环境变量：

```powershell
# PowerShell（当前会话）
$env:ALLDOT_VOICE_API_KEY = "你的key"
# 永久：系统属性 → 环境变量
```

上游 key 就是 nanoMuse relay 用的那把。改完重启桥。

### 用法

- 点输入框旁的 🎤 说话，松开自动转文字并派任务。最长 58 秒（百度单段上限）。
- 每条助手回复旁有 🔊，点一下朗读（上游 TTS，失败自动回浏览器朗读）。
- 没配 key 或上游挂了，按钮会自动切到浏览器 Web Speech，功能降级但不报错。

### 桥新增路由

| 路由 | 用途 |
|---|---|
| `GET /api/token` | 聊天页取桥 token（修掉了前端一直在调但服务端没实现的 bug） |
| `GET /api/voice/status` | 前端探测上游是否可用，决定用上游还是浏览器兜底 |
| `POST /api/voice/transcript` | 录音（webm）转文字，返回 `{ok, text}` |
| `POST /api/voice/speech` | 文字转 MP3，返回音频字节 + `X-Voice-Engine` 头 |

### 中文音色

`voice` 字段传 OpenAI 的音色名，上游映射到百度基础音色：
- `alloy` → 度小美（女）
- `echo` → 度小宇（男）
- `nova` → 度逍遥（男）

精品音库单独计费，没接进来。

## 三、购物渠道

抖音商城、拼多多、淘宝、京东、外卖（美团/饿了么）**没有对个人开放的稳定 API**，唯一可行路径是已登录浏览器（`logged_browser` 手，8931 端口，带用户 cookie）。

操作指引写在技能库里，工人通过 `skillbook` 工具读取。2026-11-26 把技能库从 585 条收窄到 10 条（通用做法 9 + 本地购物 1），并给购物技能补了英文关键词，`skillbook search shopping / taobao / food delivery` 都能命中。

### 硬规矩

1. **绝不自动付款**。走到结算/支付停下，出请示卡让人确认。
2. **登录和验证码交人手**，不绕过。
3. **只用已登录浏览器**，干净浏览器没登录态。
4. **每步截图留证**，价格规格照原文转述。

### 闸门配了什么

`gate/keywords.ts` 的 5 档身份与钱词表加了「结算/购买/买单」，配合已有的「支付/付款/登录/验证码」；4 档不可逆提交已有「下单/提交」。购物动作一定走请示卡，不会闷头执行。

### 能力边界

只能操作网页版。微信内小程序商城、抖音 App 内商城、必须 App 才能下单的品类做不了，遇到直接说清楚。
