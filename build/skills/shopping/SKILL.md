# 国内购物与外卖渠道操作（alldot 本地技能）

## 适用渠道

| 渠道 | 网址 | 已登录浏览器入口 |
|---|---|---|
| 淘宝 | https://www.taobao.com | logged_browser 手 |
| 京东 | https://www.jd.com | logged_browser 手 |
| 拼多多 | https://www.pinduoduo.com | logged_browser 手 |
| 抖音商城 | https://www.douyin.com | logged_browser 手（抖音网页版，商城入口） |
| 外卖 | 美团 https://www.meituan.com / 饿了么 https://www.ele.me | logged_browser 手 |

这些平台都没有对个人开放的稳定商品/下单 API，唯一可行的路径是**已登录浏览器**，靠 snapshot + 视觉判断 + 点击操作。不要尝试爬接口或模拟签名。

## 硬规矩（违反即停）

1. **绝不自动付款**。走到「提交订单 / 确认支付 / 结算」就把控制权交还人，出请示卡。闸门把「结算/购买/买单」判为 5 档身份与钱，「下单/提交」判为 4 档不可逆提交，都必须人点确认。
2. **登录和验证码交人手**。snapshot 里出现「登录」「扫码」「验证码」「滑块」「短信验证」立刻停，告诉用户本人来登录/验证。不要试图绕过。
3. **只用 logged_browser 手**（8931 端口，带用户 cookie）。干净浏览器（8932）没有登录态，搜得到但加不了购物车。
4. **每一步截图留证**。加购、改数量、选规格后各截一张，结果里附上，让人能核对。
5. **价格、规格、店铺名照原样转述**，不要自己四舍五入或猜。用户问「多少钱」就从页面原文读。

## 标准流程

### 搜索与比价（1-3 档，可直接做）

1. `browser.navigate` 到目标站首页（用户没指定就在淘宝/京东之间选，问过就用用户说的那个）。
2. `browser.snapshot` 找搜索框，`browser.type` 输入商品名。
3. `browser.click` 搜索，等页面稳定后 `browser.snapshot` 提取：商品名、价格、店铺、销量、是否自营。
4. 多个商品时列成表给用户，标出最便宜的和销量最高的，等用户选。

### 加购物车（2-3 档，可逆）

1. 用户选定商品后 `browser.click` 进详情页。
2. `browser.snapshot` 找规格（颜色/尺寸/数量），按用户说的选。用户没说规格就停下来问，不要默认。
3. `browser.click` 加入购物车，截图确认。
4. 回一句「已加购物车：商品名 ×数量，单价 ¥X。要我去结算吗？」

### 下单前的请示（4-5 档，必须人批）

1. 用户说「下单」后，导航到购物车，勾选指定商品。
2. 走到订单确认页，把订单摘要原文抄下来：商品、数量、总价、收货地址、运费。
3. **停下来出请示卡**，选项给「确认去结算 / 取消」。收货地址不是用户指定的也要在卡里点明。
4. 用户批准后才点「提交订单」。**支付密码/短信验证/指纹一律交人手**，agent 不碰。
5. 下单成功后把订单号、金额、商品原文报给用户。

### 外卖

1. 外卖平台先定位地址。地址不对就停，问用户送到哪。
2. 选店 → 选菜 → 加购物车 → 到结算页请示，同上。
3. 外卖时效和配送费会变，提交前重新读一遍页面原文再报给用户。

## 常见坑

- **抖音商城**网页版和 App 布局不同，snapshot 里找不到商城入口时不要瞎点，截图问用户。
- **拼多多**「仅退款」「砍一刀」这类诱导按钮不要碰，只读商品和价格。
- **登录后跳转**：有些平台登录后跳回首页，要重新搜。
- **价格变动**：加购时的价格和结算页可能不同，以结算页为准，差了要说明。
- **页面元素漂移**：不要记坐标，每次都 snapshot 重新定位元素。
- **反爬风控**：出现「访问频繁」「验证」就停，别反复刷。

## 能力边界

本技能只能操作网页版。微信内的小程序商城、抖音 App 内的商城、需要 App 才能下单的品类都做不了，遇到就说清楚，不要假装完成。没有账号或没登录时先让用户本人登录。
