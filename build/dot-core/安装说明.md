# dot-core 安装说明

这份文档写的是**装的时候要动什么**。本文档里的命令一条都没有在本仓库执行过；谁装谁跑。

交付形态（方案 B.4）：`build/dot-core/` 是源码目录，allbot 用 jiti **直接加载 TypeScript，不打包、不需要 node_modules**。
类型检查用 `tsc --noEmit`，类型检查器取 `C:/allbot-public/node_modules/typescript/bin/tsc`（本机实测可用）。

装上以后，dot-core 负责四件事（本版实际做到的）：

- 工人会话（`sessionKey = task:<任务号>`）的内置工具（exec/read/write/browser…）经过闸门判档、写前记账、结果落账；
- 练习手 `practice`（练习文件夹里 list/mkdir/write），同样走闸门 + 写前记账 + 第 2 档快照；
- 第 4 档动作出请示卡：任务转「等待输入」，请示卡经桥转发到 ds-bot；批准后**重新调用同一动作即可执行**；
- 每轮给工人会话注入账本锚点；网关启动时做完整性校验与恢复（A.9）。

## 0. 装之前：先备份

只有两样东西会被动到或者会新出现，都在这两处：

```bat
:: 1) allbot 主配置（本次会改它，改坏了要靠这份回去）
copy "C:\Users\1\.allbot\allbot.json" "C:\Users\1\.allbot\allbot.json.bak-20261125"

:: 2) dot 自己的目录（首次安装时不存在；升级时先留一份，里面是账本 db 和配置）
xcopy /E /I /Y "C:\Users\1\.allbot\dot" "C:\Users\1\.allbot\dot.bak-20261125"
```

不要备份/拷贝 `C:/allbot-public/node_modules`（1.5 GB，且和本插件无关）。
**不要在装之前删 `~/.allbot/dot/ledger/dot.db`**：那是账本，删了等于丢任务历史。

## 1. 放配置：二选一

配置有两个能写的位置，**两个都写时 allbot.json 里的覆盖文件里的**（未写的键仍用文件里的值）：

**A. 推荐：`~/.allbot/dot/config.json`**

```bat
mkdir "C:\Users\1\.allbot\dot"
copy "C:\Users\1\Documents\研究\dot\build\dot-core\config.example.json" "C:\Users\1\.allbot\dot\config.json"
```

然后把 `practice.root` 从 `null` 改成**练习文件夹的绝对路径**：

```json
{ "practice": { "root": "C:\\Users\\1\\Documents\\练习" } }
```

**B. 或者：`allbot.json` 的 `plugins.entries.dot-core.config`**（字段与本插件清单 `allbot.plugin.json` 的 `configSchema` 一致）。
这条路需要插件先被 `plugins.allow` 放行（见第 2 步），且清单校验不过会导致插件加载失败。

`practice.root` 不填，最小那只手会拒绝所有动作（`practice_root_missing`），不会自己猜目录。
其余字段的含义与缺省值见 B.4；不认识的键名、类型、范围会当场报错（`ConfigError`），不会静默忽略。

## 4. 起服务后：怎么确认「装好了」

以下每条都是可观察的事实，不是感觉：

1. **插件加载日志**（网关日志里出现，前缀 `[dot-core]`）：
   - `启动断言通过：tasks_disabled（allbot tasks.enabled 未开（默认关））`
   - `启动断言通过：compaction_safeguard（compaction.mode=safeguard）`
   - `账本 ... 就绪（schema N，应用迁移 M 条）`
   - `心跳：C:\Users\1\.allbot\dot\state\dot-core.heartbeat（间隔 60000ms）`
   - `已注册工具 practice（练习文件夹三件事，走闸门 + 写前记账 + 快照）`
   - `已注册内置工具钩子（工人会话里每个工具都过闸门并记账；process/subagents 等直接拒）`
   - `已注册 before_prompt_build 锚点钩子（只管 task:* 工人会话）`
   - `恢复协议：恢复了 N 个任务（...）`，随后 `恢复协议已在加载时执行；gateway_start 钩子（typed）再兜一次`
     （钩子必须是 typed：`api.registerHook` 写的注册表不在 `hasHooks` 的检查范围里，等于写了不执行）
   - `已挂桥路由（token ...，keep ...）`
   - `派发器已就位（dispatch.enabled=true，间隔 5000ms，单会话 600000ms，运行时 可用/不可用，停止钩子 typed）`
     - **运行时 不可用**：这套安装的构建解析不到插件运行时模块（`api.runtime.subagent` 取属性就抛
       `Unable to resolve plugin runtime module`），派发器待命、不派发，日志里只有这一行 warn；
       工具/闸门/锚点/桥路由照常。要让派发真跑，得用带插件运行时的构建。
     - 运行时 可用：接着看 `派发器启动：每 5000ms 扫一次 queued ...`、`派发前完整性校验：...`、
       `任务 task_... 已派发（runId=...）`。
     - 想停派发：`~/.allbot/dot/config.json` 里加 `{"dispatch":{"enabled":false}}` 再重启网关。
2. **账本文件生成**：`C:\Users\1\.allbot\dot\ledger\dot.db` 存在，旁边有 `-wal` / `-shm`。
3. **心跳心跳着**：`C:\Users\1\.allbot\dot\state\dot-core.heartbeat` 存在，内容形如
   `{"pid":1234,"at":"2026-11-25T...","version":"0.2.0","plugin":"dot-core"}`；
   隔一分钟再 `type` 一次，`at` 应该变了。keeper 的 dot-core 行应从黄变绿（`keeper.ps1` 的 `Get-DotCoreProbe`）。
4. **配置生效**：日志里 `配置：C:\Users\1\.allbot\dot\config.json；练习根 <你填的路径>`（若用第 1 步 B，会多一行 `已叠加 plugins.entries.dot-core.config`）。显示 `(未配)` 就回去看第 1 步。
5. **两个钩子真的在跑**：
   - 让工人在 `task:<task_id>` 会话里说一句话，模型的系统提示词里应出现 `【dot 锚点】任务 task_...`；
   - 让模型调一次 `practice`（`action: "list"`），工具返回练习文件夹内容，账本 `steps` 里多一行 `tool=practice`、`tier=1`；
   - 让工人 `read` 一个文件，`steps` 里应多一行 `tool=read`、`tier=1`、`side_effect=safe`。
6. **第 4 档与审批**：让工人 `exec` 一条命令（现网 exec 不在白名单，按第 4 档处理）：
   - 本轮被拦，返回「等批准 #N，请结束本轮」；
   - 账本 `approvals` 多一行 `pending`，任务状态变成 `awaiting_approval`（进度卡的「卡在谁」写「等你点」）；
   - 请示卡经桥转发（日志 `请示卡 #N 转给桥：...`；桥没起/没 token 会是一条 warn，不会假装成功）；
   - 你点同意（`decideApproval` → approved）后，让工人**重新调用同一动作**，这次应真的执行，审批单从 `approved → executing → executed`，任务回到 `running`。
7. **第 2 档快照**：`practice` 覆盖写一个已存在文件，`~/.allbot/dot/snapshots/<task>/<时间戳>/` 下应出现旧内容的副本，账本 `snapshots` 多一行 `kind=copy`。
8. **拒绝也生效**：让模型用 `practice` 写 `../外面.txt`，预期出请示卡（`tier=4`）；即便你点了同意，执行时仍会被路径围栏拒绝（`动作没有完成：路径跑出了练习文件夹`），审批单记 `failed`，练习文件夹外**没有任何新文件**。

任何一条不符合，按第 6 条回滚。

## 5. 两条必须记住的失效模式

**(a) 工人会话之外的 exec 不归 dot-core 管。**
`tools.exec` 保持放开（现网 `full`）。dot-core 的内置工具钩子只对 `sessionKey = task:<id>` 的工人会话判档、
记账与拦截；主会话、脸（ds-bot）会话里的 exec 仍走 allbot 自己的审批体系。这是 A.7 的口径（工人动作必须能归到
task_id），不是遗漏——但**别把「装了 dot-core」理解成「所有 exec 都有闸门」**。

**(b) dot-core 加载失败时，靠 keeper 停网关（fail-closed）。**
触发条件与行为：

- 账本打不开、migrate 失败、A.7 两条断言不过 → `register()` 直接抛异常，allbot 判定插件加载失败；
  断言在**开账本之前**做，断言失败不会留下建了一半的 `dot.db`，也不会写心跳。
- 插件不再运行 → 心跳停止刷新；`build/tools/keeper.ps1` 的 `Get-DotCoreProbe` 在心跳超过 **600 秒**后判
  「未加载」，按 fail-closed 停 18789（上限每小时 3 次，避免起停循环）。
- 注意时间窗：从插件挂掉到 keeper 停网关最多 10 分钟。这 10 分钟里工人会话里的 exec 没有闸门。

**(c) 两条已知的能力边界（本版没做，装在现网也不会自动补上）：**

- 内置 `exec` 的第 2 档（工作区内写）**不拍快照**：一条命令会改哪些文件，执行前不可知。
  步骤里会记 `snapshot: "unavailable_exec"`。真拍快照的只有练习手 `practice`。
- 待批的 `exec` 被拦下后，批准了不会自动重放：需要工人（或你）**重新调用同一动作**。
  A.6 的「批准后由 dot-core 重新派发」没做。

## 6. 回滚（三分钟）

```bat
copy /Y "C:\Users\1\.allbot\allbot.json.bak-20261125" "C:\Users\1\.allbot\allbot.json"
```

- 只想停插件、保留账本：把 `"dot-core"` 从 `plugins.allow` 里删掉，`plugins.load.paths` 里的目录可以留着。
  **同时处理心跳**：删掉 `~/.allbot/dot/state/dot-core.heartbeat`，否则 keeper 会继续读到它，
  600 秒后判「未加载」并停网关（那是 fail-closed 的正常行为，长期停用时要知道）。
- 连账本一起回退：用第 0 步的 `dot.bak-20261125` 覆盖 `~/.allbot/dot`（会丢掉这期间的任务历史，慎用）。

回滚后重启网关。仓库里没有任何东西会自动改 `allbot.json`，回滚只能靠手或你自己的脚本。
